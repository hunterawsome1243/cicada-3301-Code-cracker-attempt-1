# Reports: publication format

Everything under `reports/` (lane reports, `scorer_power.md`, drafts of anything Hunter may post)
is written for an expert audience that is rightly allergic to overclaiming. Posting outside this
repo is Hunter's call, never Claude's (HIT_PROTOCOL.md §10).

1. **Not a solve, first.** The first line of any negative is `not a solve`. The title names the
   warning or the tool, never a verdict.
2. **Reusable parts before results.** Lead with what another solver can use without trusting us:
   the canon hash (`023312066df471005264b9cbe7997cb77d2a9a6a2dc9b3316d22674023af1585`, 12,956
   runes, `numbering: "LP2-0-57"`), the validators (`scripts/check_results.py`,
   `scripts/validate_ledger.py`), the scorer power table (`reports/scorer_power.md`) and the
   decoder presets.
3. **Negatives before anything found.** "What we re-ran and got nothing from, so you don't have
   to", one entry per lane, each with its reproduce command. Then, if there is one, the single
   thing found.
4. **Coverage with numbers.** Every negative states coverage and `not_covered` as counts and
   fractions of the stated space ("181,696 keys of a 2^32 space", not "the PHP family"). Partial
   coverage is called partial. Bounds, not verdicts: write coverage / not_covered / reopens_if.
5. **The three conditionals on every negative:** key space swept · decoder transition model ·
   adjudicator register. A negative missing one says so ("English-register only, rigid decoder
   only").
6. **Reproduce from a clean checkout.** Each number sits next to the command that regenerates it,
   with the git SHA and the canon SHA-256. Include the do-not-re-run list (ledger ids) and what a
   legitimate re-run would need.
7. **Ledger-shaped fragment.** Each lane ends with a fragment Dukotah's `validate_ledger.py`
   accepts: `id, lane, hypothesis, status, threshold, threshold_fixed_in_advance,
   positive_control, control_detail, null, result, coverage, not_covered, evidence, reproduce,
   reopens_if`, plus our `numbering`, `conditionals`, `external_ids`, `data_sha256`, `git_sha`.
   Cite upstream work by round and lane file (e.g. "Round 12 front D3"), not by repository.
8. **Leads** (only after HIT_PROTOCOL.md step 8): publish the key module, the forward-encryption
   script and its SHA-256, both oracle JSONs and the clean-checkout command; say what was not
   checked and invite refutation. Never claim an LLM solved anything.
9. Vocabulary is the same as in RESULTS.md: no "exhausted", "closed", "unsolvable", "confirmed",
   "cracked", "the frontier is complete", or "solved" outside "the nine solved sections".
   Reports generated by code are published regardless of outcome.
