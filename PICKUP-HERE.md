## Lessons

- 2026-10-22, instrument (FOUND-ERROR, own toolbox): `interrupt_prob` defaulted to 0.44, reading "WELCOME 11 of 25" as P(a plaintext F is an interrupter). It counts ciphertext ᚠ's; every plaintext F in the keyed solved sections is an interrupter (14/14). Default corrected to 1.0 (`runeforge/lanes.py`); frozen docstrings carry the same misreading (TR-4). Consequence, measured: under the every-F rule the template lane's family fails the gate on C1 in 12/12 keys (`python scripts/beam_power.py`, gate section). LP2 0-55 holds 458 ᚠ against 446.8 for uniform runes, where English-register plaintext with every F unencrypted would put ~650-780. So the gate-passing family is anti-repeat without interrupters (`interrupt_prob: 0.0` passes cleanly); the earlier "GATE PASS, marginal C3" below was measured at the misread 0.44.
- 2026-10-22, instrument: the spec's "rigid screen, beam on survivors" cannot see a filtered key -- a rigid decode of a planted anti-repeat key scores like noise (control 0/20), so it never reaches the survivors. Rule 2 (the control runs the sweep's own pipeline) puts the beam in the screen itself: a `:beam*` lane decodes every key with the beam in its control, nulls and sweep. CPU cost ~1,000-2,500 keys/s at L = 240 (beam ~2,500, beam-skip ~1,240, beam-skip-int ~1,000) against about 10^5 rigid (`reports/beam_decoder.md` §6, noise).
- 2026-10-22, calibration: a beam lifts wrong-key noise above uniform strings (it picks the best interrupt/skip path through the wrong key): at L = 240 with lp-ngram3-heldout the wrong-key mean is -6.90 (beam), -6.87 (beam-skip), -6.74 (beam-skip-int) against -7.17 rigid (`scripts/beam_power.py` noise). Beam bars therefore come from beam nulls (`runeforge/scoring/beam_calib.py`), never from the rigid calibrations.
- 2026-10-22, calibration (adversarial review): an interrupt decoder's wrong-key null rises with the window's canonical F count (`beam`, L = 240: block-max mean -6.57 at 4 F's, -6.32 at 20, `scripts/beam_power.py` fcount; `beam-skip` flat), so a bar fitted on fresh uniform ciphers sits below an F-rich window's own null. `beam` / `beam-skip-int` bars are fitted at the most F's of any LP2 page-start window (L = 120: 10, page 43; L = 240: 14, page 11) and a lane whose window holds more is not runnable. The first-round fits (uniform ciphers, max_skip 2) were withdrawn before anyone installed them.
- 2026-10-22, instrument: under the rigid decoder no lane can pass both the fingerprint gate and its planted control. LP2's doublet deficit (86 vs 447 expected) is reproduced only with the anti-repeat filter (`runeforge gate lanes/_template.yaml`: GATE PASS, marginal C3 C6); without it the doublet rate is ~5x LP2's and the gate excludes the family. But the rigid decoder cannot follow the filter's key skips, so the control of every filtered lane is `INCONCLUSIVE (power)` (`runeforge control lanes/_template.yaml`: recovered 0/20). Every lane today therefore ends `EXCLUDED (gate)` or `INCONCLUSIVE (power)`; the Phase 2 beam decoder is the critical path, not more sweeping.
- 2026-10-22, instrument: the oracle cannot tell a one-time pad from a key (k = c - p maps any page to English and passes, `tests/test_oracle_cli.py`). A key's provenance -- generator, seed, and the bar at the lane's true N -- is what HIT_PROTOCOL.md steps 4-5 check; `--key-module` must be the generator's own keystream (`--lane` decodes it the lane's way).
- 2026-10-22, calibration: the Gumbel extrapolation from block maxima errs conservative -- the single max of 10^6 null draws fell below the predicted mean max in all 8 fits (`runeforge/scoring/calib/presets/*.json`, `check`), so bars at 2^32 are slightly high (fewer false positives, slightly less power).
